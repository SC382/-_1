# 智慧胸痛中心管理系统 · 系统流程图

> 核心业务链路 + 各功能模块的作用与关联。v3.1.0

---

## 一、核心业务主流程

```
医生(App)                 审核员(Web)              医生(App)
   │                          │                        │
   ▼                          ▼                        ▼
①患者建档 → ②模板填报 → ③提交审核 → ④审核 ──通过──→ ⑤自动生成随访 → ⑥随访执行
   │          │        │  (时间链校验)  └─驳回──→ 整改→再提交         │
   └──────────┴────────┘                                              └ 完成/过期
```

| 步骤 | 角色 | 作用 | 状态流转 |
|---|---|---|---|
| ① 患者建档 | 医生 | 生成病例编号、基础信息（AI 可预填） | - |
| ② 模板填报 | 医生 | 按模板动态表单填写（6 分类，可存草稿） | draft |
| ③ 提交审核 | 医生 | 校验必填+时间链后提交 | → submitted |
| ④ 审核 | 审核员(Web) | 工作台→待审→详情→通过/驳回 | → approved / rejected |
| ⑤ 通过后 | 系统自动 | 生成 1/3/6/12 月随访计划 | 写 follow_up |
| ⑥ 随访执行 | 医生 | 到期提交随访（用药/风险/存活） | pending → submitted/overdue |

## 二、各功能的作用与关联

| 功能模块 | 作用 | 关联到 |
|---|---|---|
| **模板管理** | 定义填报表单（字段/分类/发布） | ②填报：表单来源；改模板不影响已存数据（form_data JSON） |
| **AI 助手·识别** | 图片/文字识别自动预填、知识问答 | ②填报辅助、医生学习 |
| **远程心电** | 心电 AI 诊断 + 协同会诊 | 关联病例（可选），独立状态机 |
| **三会 PPT** | 从病例数据生成会议材料 | ①-⑥病例数据聚合 |
| **公告/增值/学院** | 运营内容发布与医生学习 | Web 发布 → App 首页/入口展示 |
| **驾驶舱/统计** | 全中心数据汇总（KPI/趋势/排行/质控） | ①-⑥ 全部数据实时聚合 |
| **今日报告** | 医生当日病例概览 | ②③ 今日病例状态分布 |
| **操作日志** | 全流程留痕 | 所有写操作自动记录 |

## 三、跨端协作关系

```
Web 管理端（配置/审核/统计）
   │ 模板、公告、增值服务、学院、医院、用户、审核
   ▼
后端 FastAPI（动态路由 /cpx）
   │ JWT + BusinessRole 三档权限
   ▼
App 医生端（填报/执行/学习）
   │ 病例、随访、心电、三会、AI
   ▼
驾驶舱/日志（数据回流可视 + 留痕）
```

## 四、关键状态机

```
病例：draft → submitted → approved ──→ 自动生成随访(pending → submitted / overdue)
                        └→ rejected →（医生整改）→ submitted
心电：draft → uploaded → consult_sent → received → closed
公告：draft / published / offline ｜ 增值服务：draft / online / offline
```
