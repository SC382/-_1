## 2. 多端适配机制（代码级证据）

### 2.1 条件编译分布（来自 `src/` 实扫）

| 平台标识 | `#ifdef`/`#ifndef` 出现次数 | 主要覆盖点 |
|---|---|---|
| H5 | 52 | 定位（浏览器原生 `navigator.geolocation`）、页面切换动画、基座路径 |
| APP / APP-PLUS | 44 | 原生定位 `uni.chooseLocation`、推送、原生模块 |
| MP（全部小程序通用） | 43 | 分包、组件兼容、API 差异 |
| MP-WEIXIN | 26 | 微信登录 `uni.login({provider:'weixin'})`、分包优化、动画裁剪 |
| 第三方组件（mp-html 等） | 约 83 | 非业务代码，库自带 |

> 业务代码中约 **50 处**条件编译，集中在定位、登录、存储、网络请求四类能力，说明平台差异已被**收敛到少量适配点**而非散落全局。

### 2.2 API 基地址动态解析（核心跨网适配）

`src/http/adapters/alova.ts` 的 `getApiBaseUrl()`：

- **H5 开发模式**：自动取 `window.location.hostname:8002` → 换电脑 / 换网络（IP 变更）**无需改任何配置**即可联调后端。
- **非 H5 或生产构建**：回退到 `.env` 的 `VITE_API_BASE_URL`。
  - `.env.development`：`http://192.168.37.159:8002`
  - `.env.production`：`http://106.55.33.111`（公网服务器）

> 这是解决"多端多网络环境"的关键设计，避免每个端硬编码 IP。

### 2.3 平台专属能力适配

| 能力 | H5 端 | 非 H5（App/小程序） | 证据 |
|---|---|---|---|
| 定位 | `navigator.geolocation`（浏览器原生，免地图 key） | `uni.chooseLocation`（需高德 key，仅 App 打包内置） | `pages/case/create.vue` L197-383、`pages/case/fill.vue` L416-442，均用 `#ifdef H5` 分支 |
| 微信登录 | 不支持（降级提示「仅微信端」） | `#ifdef MP-WEIXIN` 才走 `uni.login({provider:'weixin'})` | `composables/useWxLogin.ts` L39-49 |
| 存储 | 平台统一封装，按端分实现 | 同左 | `utils/storage.ts` 含 `#ifdef` 分支 |
| 请求/鉴权 | 统一 alova 实例，401 自动刷新 + 重放 | 同左 | `src/http/adapters/alova.ts`（无平台分支，靠基座动态解析） |

### 2.4 构建配置与多平台声明（manifest.config.ts）

`manifest.config.ts` 声明了 **15+ 平台**的构建目标，关键真实项：

- **app-plus（Android/iOS）**：
  - `modules`: Maps + Geolocation（地图 + 定位）
  - `permissions`: 含 `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`
  - `packagename`: `com.cpx.xiongtong`
  - `sdkConfigs.maps.amap.appkey_android`: `3c2567a679ca628a8f0f5d74934241f4`
- **mp-weixin**：`optimization.subPackages: true`、`setting.urlCheck:false`、声明 `appid`
- **h5 / mp-weixin**：均声明 `darkmode:true` + `themeLocation:'theme.json'`
- **mp-alipay / mp-baidu / mp-toutiao / mp-qq / app-harmony / mp-harmony** 等：仅声明 `usingComponents`，无平台专属配置

### 2.5 页面路由与分包（自动发现 + 平台裁剪）

- `pages.config.ts` 的 `pages: []` **是故意为空** —— 页面由 `@uni-helper/vite-plugin-uni-pages` 自动从 `src/pages/**/*.vue` 发现并生成 `pages.json`（每次构建重写，故**勿手改 `src/manifest.json` 产物**）。
- `globalStyle` 按平台动态裁剪：`animationType/animationDuration` 在微信端排除（`window` 不支持）；`tabBar` 的 `customize/overlay` 仅支付宝端添加。
- `mp-weixin` 开启分包优化；真实产物 `app.json` 实测含主包 + 分包页面。

## 6. 结论

1. **适配机制正确且收敛良好**：平台差异通过 `#ifdef` 条件编译（约 50 处业务代码）、动态 API 基地址、统一请求层三层隔离，未出现大规模平台分支散落。
2. **三端 H5 实构建通过**：医生端 H5（`dist/build/h5/` 155 文件）与 Web 管理端 H5-PWA（`dist/` 静态含 `.gz/.br` 预压缩）均成功产出可部署产物；两端安卓 APK 均经 manifest/配置核查具备云打包/封装条件，本环境受限于云打包与封装工具未实跑。
3. **发布前置（P1）已降级为按需**：微信小程序真实 appid、其它小程序平台账号配置，因小程序非实际分发端，不阻塞当前投产，仅在计划启用时处理。
4. **建议修 1 项（P2）**：医生端 H5/小程序构建的循环依赖告警，虽不阻断构建，但属潜在运行时风险，应尽早消除。
5. **安卓 APK（医生端 + Web 管理端）未在本机验证**：医生端需 HBuilderX 云打包与签名证书，管理端需外部封装工具（WebView 包 H5），均属环境限制而非代码缺陷；配置已齐备。
