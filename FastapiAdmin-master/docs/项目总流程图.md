## 二、分块说明

### 1. 角色与权限
- **admin**：Web 全量管理（模板/医院/用户/内容/统计）+ 查看全库病例
- **auditor**：Web 审核工作台（待审→详情→通过/驳回）+ 医院/模板只读
- **doctor**：App 填报/随访/心电/三会/学习/AI

### 2. 三端功能（详见功能架构图）
- Web：管理中枢（配置/审核/统计/发布）
- 后端：业务中枢（动态路由/校验/状态机/数据）
- App：业务执行（填报/随访/心电/AI）

### 3. 核心业务主链
```
建档(患者信息) → 填报(模板动态表单,AI预填) → 提交(submitted)
→ 审核(Web,时间链校验) → 通过(自动生成1/3/6/12月随访) / 驳回(整改再提交)
→ 随访执行(用药/风险/存活)
```

### 4. 数据与外部服务
| 服务 | 用途 |
|---|---|
| MySQL 8.0 | 20 张业务表 + form_data JSON 动态表单 |
| Redis 7 | 会话 cpx_session、系统参数、字典、定时任务 |
| DeepSeek API | deepseek-v4-flash(问答/文字) · deepseek-v4-flash-vision-exp(图片) |
| 外部能力 | 文件上传(static/uploads)、三会 PPT 生成、H5 定位 |

## 三、关联闭环

```
Web 配置(模板/公告/增值/学院) → App 使用/展示
App 填报 → Web 审核 → 自动随访 → App 执行
App 数据 → Web 驾驶舱/大屏汇总
全程写操作 → 系统日志留痕
```
