## 二、后端代码架构（backend/）

### 2.1 分层与目录
```
backend/app/
├── core/        # discover(动态路由) / database(双引擎) / exceptions(全局异常) / ap_scheduler / base_model / dependencies
├── config/      # pydantic-settings 单例（env/.env.dev → MySQL/Redis/Qwen）
├── common/      # response.py(SuccessResponse/ErrorResponse) / enums.py(RET)
├── api/v1/      # 框架静态路由：system/ai/storage/task/monitor/generator/common（20,639 行）
├── plugin/      # module_cpx 业务插件（49 文件 8,185 行）+ module_example
├── scripts/     # initialize / init_cpx_data / seed_dashboard_data
└── utils/       # password / excel / upload 等
```

### 2.2 核心机制
- **create_app 工厂**（`main.py:18`）：注册异常→中间件→路由→静态→Swagger；typer CLI 提供 `run/revision/upgrade`
- **lifespan 初始化链**（`init_app.py`）：建表 → Redis 连接 → 参数/字典缓存 → 定时任务调度器（AsyncIOScheduler + Redis/SQLAlchemy 双 jobstore）
- **动态路由自动发现**（`core/discover.py:46`）：扫描 `plugin/module_*/**/controller.py`，目录名即路由前缀（`module_cpx` → `/cpx`），模块内顶层 `APIRouter` 自动挂载——**新增业务模块零路由注册**
- **双数据库引擎**（`core/database.py`）：同步 pymysql + 异步 aiomysql，SQLite 走 WAL
- **全局异常体系**（`core/exceptions.py:41`）：`CustomException(msg, code, status_code, data)` + 7 个 handler 统一转 `ErrorResponse`，生产环境隐藏内部细节

### 2.3 业务插件分层（module_cpx 12 模块）
```
controller.py  XxxRouter = APIRouter(prefix=...) → Depends(BusinessRole([...])) → service.xxx() → SuccessResponse
service.py     __init__(auth: BizAuth, db) → 业务逻辑，异常抛 CustomException
schema.py      纯 pydantic Create/Update 模型
```
- **权限模型独立于框架**（`auth/dependencies.py`）：JWT → Redis `cpx_session:{sid}` → 实时查 `user_account`+role+hospital；`ROLE_ADMIN/AUDITOR/DOCTOR` + `ROLE_CODE_MAP`
- 写操作统一经 `LogService.create` 留痕（操作日志）
- 最重模块：`doctor`（service 2,322 行，controller 602 行）

### 2.4 数据模型（models.py，20 张表）
`hospital / role / user_account / doctor_info / auditor_info / case_record / case_detail / audit_record / report_template / template_field / follow_up / treatment_unit / ecg_consult / meeting_record / academy_content / system_log / statistic_daily / ai_kb_chunk / announcement / value_added_service`

**模板驱动动态表单**：`template_field` 定义字段（tab 分组、必填、类型），业务值存 `case_detail.form_data`(JSON)，`fields.py` 提供三端共用标准字段字典——表单结构可配置、病例数据标准化。

### 2.5 脚本
- `initialize.py`：check_db → create_tables → 按依赖序灌 JSON 种子数据（幂等跳过）
- `init_cpx_data.py`：角色/演示医院/admin(Admin123)
- `seed_dashboard_data.py`：近 12 个月病例+审核演示数据（≥60 条跳过）

## 三、Web 管理端代码架构（frontend/web/）

### 3.1 工程与工程化
Vue 3.5 + Element Plus 2.14 + ECharts 6 + Pinia 3 + vue-router 5 + Tailwind 4；`unplugin-auto-import`/`unplugin-vue-components` 自动按需注册，`manualChunks` 大库分包，生产 gzip/brotli。`App.vue` 含全局快捷键（Ctrl+S 提交）、错误边界、离线监听。

### 3.2 路由/菜单双轨制（核心设计）
`MenuProcessor.ts` 按 `useAppMode` 分三种模式：
- **前端内置菜单**（`builtinFrontendRoutes`，胸痛业务走此路，24 条顶级路由，前缀 `/cpx-xxx` 避让后端 `/cpx`）
- **后端菜单表驱动**（`MenuTable` 递归映射 + meta 对齐 keep_alive/affix/iframe）
- **混合合并**

非超管按 `meta.roles` 递归过滤；`guards.ts` 守卫：登录校验 → 恢复会话 → 拉菜单 → 动态注册路由 → 无权限回首页。

### 3.3 请求层（健壮性亮点）
`utils/http/index.ts`：axios 实例 + **401 静默刷新**（`isRefreshing` 标志 + `pendingRequests` 重放队列 + `_retried` 防死循环）、blob 直通、业务码校验、GET 不弹成功。api 统一模式：类型 + `API_PATH` + 对象方法（list/detail/create/update/remove）。

### 3.4 状态与页面
- 10 个 Pinia store（user/app/chat/config/dict/menu/notice/setting/table/worktab），persistedstate；**双登录体系**（框架登录 + 业务登录 `businessLogin` 注入 role_code）
- 页面模式：dashboard（444 行，数字滚动+骨架屏+3 图）手写；CRUD 页（announcement 282 行）搜索栏→表格→分页→弹窗表单→二次确认，框架层另有 `useTable/useCrudForm/useCrudDialog` hooks（module_system 复用）
- 自定义组件约 90 个（forms 18 / charts 9 / cards 10 / tables 6 / modal 6）

## 四、App 医生端代码架构（frontend/app/）

### 4.1 工程配置（uni-app 现代化）
基于 wot-starter：**无物理 pages.json/manifest.json**，由 `pages.config.ts`/`manifest.config.ts` 编译生成（`vite-plugin-uni-pages` 系列）；请求用 **alova 3.5 + @alova/adapter-uniapp** 而非裸 uni.request；`@uni-helper` 全家桶 + unocss + 自动按需引入。

### 4.2 请求封装（alova 模式）
`adapters/alova.ts`：timeout 120s、`cacheFor:{GET:0,POST:0}`、请求拦截注入 token（`meta.ignoreAuth` 免鉴权、`meta.domain` 动态 baseURL）、**401 并发队列刷新重放**、`code!==0` 统一 `throwApiError`（优先后端 msg）、网络错误全局 toast（`meta.silent` 可内联）。

### 4.3 状态与导航
- Pinia + 自研 `persist.ts`（uni storage 持久化）；userStore 防重入登录、logout 重定向
- 自定义底部导航 `layouts/tabbar.vue`（wd-tabbar + `useTabbar` 模块级 ref 管理 home/ai/mine，中间 AI 渐变块差异化）
- 37 个页面：主包 28（index/work/analysis/followup/unit/meeting/academy/ecg/triage/case/ai/mine/login/selfcheck…）+ 分包 9（announcement-detail、notices、profile、setting 等），`definePage({name, layout, style})` 注册

### 4.4 国际化
vue-i18n 9，zh.json(382 行)/en.json(381 行) 结构对称，locale 持久化，默认 zh-CN。

## 五、关键设计模式汇总

| # | 模式 | 位置 | 价值 |
|---|---|---|---|
| 1 | **插件化动态路由** | `core/discover.py` | 新增业务模块 = 建目录 + 写 controller，主程序零改动 |
| 2 | **模板驱动动态表单** | `template_field` + `case_detail.form_data` | 表单结构可配置、多版本、三端字段字典统一 |
| 3 | **三级业务权限** | `auth/dependencies.py` | JWT+Redis 会话实时校验，接口级 `BusinessRole` 隔离 |
| 4 | **双登录体系** | Web `user.store.ts` | 框架后台与业务系统（胸痛）并存于同一套前端 |
| 5 | **token 静默续期** | Web http / App alova | 401 并发队列重放，用户体验无缝 |
| 6 | **三端共用标准字段** | `plugin/module_cpx/fields.py` | 后端/Web/App 病例字段定义同源 |
| 7 | **自定义底部导航** | App `layouts/tabbar.vue` | tab 图标/样式可完全定制（AI 渐变块） |

## 六、代码质量观察（供后续优化参考）

- ✅ **分层清晰**：controller/service/schema 三件套统一，Web/App 均按模块组织
- ✅ **健壮性**：双端请求层均有 401 刷新重放；后端全局异常收敛 + 生产隐藏细节
- ✅ **工程化**：uv + pnpm + 自动引入 + 分包压缩，构建链现代
- ⚠️ **doctor/service.py 过重**（2,322 行），建议按业务拆分（统计/建档/表单/随访/心电）
- ⚠️ Web 业务 CRUD 页多为手写模板（announcement 282 行），与框架 `useTable/useCrudForm` hooks 未完全打通，可逐步迁移复用
- ⚠️ 物理删除 + BigInteger 主键：未来若需审计/恢复，可评估软删除
- ⚠️ 演示数据脚本与真实数据混库（seed_dashboard_data），上线前需清理策略

## 七、一句话总结

> 一个**插件化动态路由的 FastAPI 后端**（12 业务模块、模板驱动病例表单、三级权限、双库双引擎）+ **双轨菜单的 Vue3 管理端**（真实数据驾驶舱、公告/增值服务运营）+ **alova 驱动的 uni-app 医生端**（37 页面、数据直报、自定义导航、中英国际化），三端共约 11.5 万行代码，覆盖胸痛中心"填报-审核-随访-质控-运营"全链路。
