# 学习路线（基于真实代码，小白入门版）

> 本文档面向**零基础**、要在这个 11 万行项目里从 0 学起的同学。所有文件路径、函数名、端口、字段数均已实地核对当前代码，不凭记忆。
> 配套先读：`项目总体描述.md`、`技术架构图.md`、`系统流程图.md`、`开发环境配置清单.md`。

## 0. 先认清项目体量，别硬啃

| 事实 | 数值 |
|---|---|
| 后端 Python 文件 | 264 个（`.py`） |
| 前端 Vue/TS 文件 | Web 198 `.vue` + 214 `.ts`；App 198 `.vue` + 214 `.ts` |
| 业务表 | 20 张（cpx 模块） |
| 标准字段 | **67 个**（`fields.py`，唯一数据源） |
| 端口 | 后端 8002 / Web 5180 / App 5190 |

**结论**：一上来读文件会在 264 个 `.py` 里淹死。正确顺序是 **先懂业务 → 跑起来 → 顺一条业务主线读代码 → 最后横向铺开**。

## 2. 阶段 1 · 建立业务心智（半天）

读文档，**不要读代码**：

| 顺序 | 文件 | 目的 |
|---|---|---|
| 1 | `docs/项目总体描述.md` | 一句话定位：胸痛中心专病质控平台，三端一大屏 |
| 2 | `docs/系统流程图.md` / `项目总流程图.md` | 患者从入院到随访全流程 |
| 3 | `docs/功能架构图.md` / `技术架构图.md` | 三端各自功能、互相怎么通信 |

**验收**：能不看文档说出"一个患者进来后系统里发生什么"——建档 → 填报（67 标准字段）→ 审核 → 质控 → 随访，以及远程心电、三会、学院等增值模块。

## 3. 阶段 2 · 跑起来（1 天，最难也最值）

按 `docs/开发环境配置清单.md` 操作。端口矩阵：

| 端 | 端口 | 入口 |
|---|---|---|
| 后端 API | 8002 | http://localhost:8002/api/v1/docs（Swagger，最好的学习工具） |
| Web 管理端 | 5180 | http://localhost:5180/ |
| App 医生端 | 5190 | http://localhost:5190/ |

**验收**：三端口都能打开，Swagger 里能真实调一次 `POST /api/v1/cpx/doctor/case/create` 建一个病例。

⚠️ **最大启动坑**：后端启动必须带 `ENVIRONMENT=dev`，否则读 `.env.None` → 数据库密码空 → `Access denied`。改后端代码后**必须手动重启**（不带 `--reload`）。

## 4. 阶段 3 · 后端骨架（1 天）

按依赖顺序读 4 个真实文件：

| # | 文件 | 行数 | 看什么 |
|---|---|---|---|
| 1 | `backend/main.py` | 126 | **全项目最该第一个读的代码**。`create_app()` 工厂函数讲完"应用由什么组成"：`lifespan`（建表/连 Redis/加载字典/起定时任务）→ `register_middlewares` → `register_exceptions` → `register_routers` → 静态文件 → 文档 |
| 2 | `backend/app/init_app.py` | — | `lifespan()` 里干了什么：`InitializeData().init_db()`、Redis 连接、`ParamsService`/`DictDataService` 缓存、`SchedulerUtil` 定时任务 |
| 3 | `backend/app/core/discover.py` | — | **本项目的灵魂机制**：`glob("module_*/**/controller.py")` 扫描，目录名 `module_xxx` 自动映射为 URL 前缀 `/xxx`（第 46、56-64 行）。看懂它，就懂"加业务模块不用注册路由" |
| 4 | `backend/app/config/setting.py` | — | 所有配置从哪来：`env_file = ENV_DIR / f".env.{ENVIRONMENT}"`（第 17 行），读 `backend/env/.env.dev` |

**验收**：能画出"浏览器发一个请求，经过哪些层到数据库，再原路返回"的完整链路图。

## 5. 阶段 4 · 啃一条业务主线（2~3 天，核心中的核心）

**别读 `api/v1/module_system`**（那是脚手架通用 RBAC/存储/任务，与业务无关）。只读 `backend/app/plugin/module_cpx/doctor/` 三个文件——这是业务心脏：

| 文件 | 看什么（已核实真实存在） |
|---|---|
| `controller.py` | 30+ 接口（`@DoctorRouter.get/post/...`），看路由装饰器和入参校验，**不要看实现** |
| `service.py` | 真正的业务逻辑。挑这三个函数串读（行号已核实）：<br>• `create()`（128 行）建档<br>• `save_form()`（217 行）保存填报 `template_id + form_data`<br>• `submit()`（237 行）提交审核 |
| `schema.py` | 请求/响应数据结构 |

**推荐读法**：在 Swagger 真实调一次 `case/create`，看日志，跟着一次请求走完 controller → service → DB → response。

**验收**：能解释"提交一个病例审核，后端校验了哪几件事、数据存到哪张表（`case_record`/`case_detail`/`audit_record`）、状态怎么流转"。

## 6. 阶段 5 · 前端两端对照（2 天）

同一个业务，两种渲染，对照着读效率最高（文件均已核实存在）：

| 端 | 页面 | 接口封装 |
|---|---|---|
| **Web 管理端** | `frontend/web/src/views/cpx/case/index.vue`（病例管理） | `frontend/web/src/api/cpx/case.ts` |
| **App 医生端** | `frontend/app/src/pages/case/fill.vue`（填报页） | `frontend/app/src/api/module_cpx/doctor.ts` |

> App 端页面与导航标题的**权威源**是 `frontend/app/pages.config.ts`，不是 `pages.json`（会被 `vite-plugin-uni-pages` 覆盖，别去改它）。

**验收**：找到"病例详情"这个功能在两端各自对应哪个文件、哪个接口、哪个组件。

## 7. 阶段 6 · 毕业作业：加一个填报字段（2 天）

检验你是否真懂的终极测试，一条链走完：

1. `backend/app/plugin/module_cpx/fields.py` — 在 **67 个**标准字段字典里加一个新字段
2. 数据库模板里把新字段挂到填报模板（`template` 模块，表 `report_template`/`template_field`）
3. `frontend/app/src/pages/case/fill.vue` — 新字段能在填报页展示和保存
4. `frontend/web/src/views/cpx/case/index.vue` — 详情页"全部填报数据"能看到它
5. **重启后端**（不带 `--reload`，必须手动重启），真实提交验证

做到这步，你就能独立在这个项目里加功能了。

## 9. 真正值得学的两大设计（学透就超过多数人）

1. **动态路由插件机制**（`core/discover.py`）：目录即路由，加模块零注册。
2. **字段字典驱动的填报体系**（`fields.py` 67 字段 → `template`/`case_detail`）：一套字典驱动 Web + App 两端表单，改字段必须两端同步，且注意 `code`/`field_code` 两套键名差异（历史上踩过：只存 6 字段导致老病例数据丢失）。

> 框架（FastAPI/Vue3）网上教程一堆，这俩设计才是本项目的学习价值所在。
